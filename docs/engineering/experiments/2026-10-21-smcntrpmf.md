# Smcntrpmf RTL and mode-transition verification (2026-10-21)

## Question and source

Can Wally count `mcycle` and `minstret` only in a selected privilege mode
while preserving the base PMU behavior? Working tree on `adding-mpu-support`
above `f1a5b7744`; target configurations generated by `make deriv`:
`smcntrpmf_rv32gc`, `smcntrpmf_rv64gc`, `pmf_rv32gc` and `pmf_rv64gc`.
Results require rechecking against any later committed revision.

```bash
make deriv
python3 tests/pmu/run.py --work /tmp/smcntrpmf-pmu
```

run on `pmf_rv64gc` through `wsim --sim verilator`: **PASS**,

## Limits

The directed tests are RTL simulation, not a Linux, board or synthesized FPGA
result. Cycle attribution at the exact trap/return edge is implementation
defined by the standard. `perf stat -e cycles:u,instructions:u` under Linux
requires a matching firmware/device tree and has not been exercised by this
record.
