## Question, setup and result

Can two actual Wally harts boot Linux and run processes on separate CPUs with
shared atomic and spinlock-protected state under the stage-3 cache contract?

- Verilator 5.022; bare-metal GCC 13.2.0 for directed tests; Linux GCC 15.2.0
  from the local Buildroot 2026.02.3-dirty toolchain.
- Linux 6.19.14, OpenSBI 1.7; `multicore_linux`, two harts, 256 cache words,
  128 MiB RAM, Sv39/Svade, private caches disabled. Static initramfs `/init`;
  UART-only kernel without VT/legacy PTYs/input/HID. These are simulation
  parameters, not physical timing or utilization constraints.
- QEMU reference: PASS, runner exit 0. Wally RTL: PASS, runner exit 0:

```text
WALLY_SMP_ONLINE cpus=2 expected=2
WALLY_SMP_PASS cpus=2 counter=128 protected=128
PASS: Linux SMP on Wally RTL after 262311969 cycles
```

`/init` checked online CPUs, worker affinity and exit status, and both final
counters. Wall time was approximately 1 h 45 min on this host. Directed
cached/uncached tests, 1/2/3-hart wait-state tests, lint and pre-commit results
are scoped in the existing branch report. This does not establish arbitrary-N
Linux coverage, full ISA/MMU coverage, MESI/DMA coherence or FPGA operation.
