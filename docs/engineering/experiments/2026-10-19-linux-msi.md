This record must not be read as the earlier shared-cache Linux PASS.

## Objective and exact platform

Execute the existing OpenSBI/Linux/userspace SMP workload on two real Wally
RTL harts with private write-back MSI data caches. NCORES=2,
PRIVATE_DCACHE=1, CACHE_WORDS=256 (2 KiB/hart, one 8-byte word/line),
SHARED_CACHE=0. The multicore_linux derivative supplies Sv39/Svade, no legacy
I/D caches or CBO extensions, Svadu/Svpbmt disabled, 128 MiB RAM and the
boot ROM. All memory accesses remain ordered by the central arbiter.
See [ADR 0003](../decisions/0003-private-msi-data-caches.md) for the MSI contract.

The new DTB announces a private D-cache on each CPU, no I-cache and no
shared-cache node. It retains the same memory, UART, CLINT and PLIC map.
A single-hart MSI request announces no cache, matching the SoC generate
bypass. Shared-mode DTS output was checked byte-for-byte against the
previous generator for 1/2/8 harts and is unchanged.

## Runner and reproduction

```bash
source ./setup.sh
python3 linux/smp/build.py --buildroot /path/to/buildroot --work /tmp/wally-linux-msi --cores 2 --cache-mode msi --cache-words 256
python3 linux/smp/run.py --work /tmp/wally-linux-msi --sim qemu
python3 linux/smp/run.py --work /tmp/wally-linux-msi --cache-mode msi
# After an interrupted/limited run, preserving source/model/image identity:
python3 linux/smp/run.py --work /tmp/wally-linux-msi --cache-mode msi --reuse --resume
```

The runner defaults to the mode/capacity in the image manifest. It rejects
explicit mismatches, changed image hashes, stale model inputs/binary hashes
and incompatible checkpoint metadata. A work-directory lock prevents
concurrent RTL builds/runs from sharing logs or snapshots. --build-only
prepares the model; --reuse checks its identity. --checkpoint selects a
snapshot path, --checkpoint-interval selects cycles, and --cycles is the
absolute total cycle limit, including time before restore.

The C++ runner saves to a temporary file and atomically renames it at a
complete cycle boundary. Snapshots include both private banks, RAM, all RTL
state, VerilatedContext, next cycle, heartbeat and partial console line.
SIGTERM/SIGINT request a final save and exit 75. Reaching the cycle limit
also saves and returns 75; neither is PASS. Guest failure/kernel panic exits
1; PASS exits 0. Stdout flushing is restricted to actual UART writes instead
of every simulated cycle. The unchanged UART datapath, timing and verdict
observation remain active.

## Local evidence and limitations

rtl.log, qemu.log; manifest.json and reuse-software.json identify images;
checkpoint-validation.json identifies the bounded equivalence check.
production-process.json identifies the initial host runner process; do not
assume that PID remains valid after a restart. start.py resumes using the
verified snapshot and refuses to restart an already passing result.

Compact logs, images, source inputs and metadata are also copied to ignored
`sim/verilator/wkdir/multicore/verification-linux-msi-20261019/`. progress.json
records the completed RTL result PASS; artifact-sha256.json identifies
that local archive's files. Raw model/snapshot files remain in the native
work directory.

These paths are host-local, not remote archives. Periodic checkpointing makes
the simulation resumable; it does not establish correctness. On interruption,
verify source/model/image identities before resuming. No FPGA, synthesis,
routing, timing, DDR, external-DMA coherence, arbitrary-N or private-I-cache
result is claimed. The earlier directed MSI checks remain scoped to their
[own record](2026-10-19-private-msi.md).
