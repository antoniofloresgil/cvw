# Sscofpmf RTL and CSR verification (2026-10-21)

## Question and source

Does optional `SSCOFPMF_SUPPORTED` implement HPM overflow, privilege filtering
and the local interrupt without changing base configurations? Tested the
working tree on `adding-mpu-support` above `92c007ae5`, with the
`sscofpmf_rv32gc` and `sscofpmf_rv64gc` derivatives and base rv32gc/rv64gc,
rv32i/rv64i. Generated configs came from `make deriv`. Results must be
rechecked against any later committed revision.

## Limits

Directed tests establish RTL CSR/event behavior, not Linux sampling, board
timing or physical FPGA behavior. The pre-M-stage event attribution caveat is
described in [ADR 0014](../decisions/0014-sscofpmf-counter-overflow.md).
Existing board DTBs do not advertise Sscofpmf because their base configs keep
it disabled. An enabled SoC needs matching firmware and OS description before
testing `perf record` or mode-filtered `perf stat` end to end.
