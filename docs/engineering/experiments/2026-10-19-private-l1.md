## Design and reproducibility

[ADR 0004](../decisions/0004-private-instruction-caches.md) defines private
I banks, eager all-hart write invalidation and read-only D-bank probes.
NCORES remains parameterized; effective features disappear with NCORES=1.
Writes, LR/SC, AMO and misses retain one global ordering point. Local read
hits can overlap each other and global read misses; writes block local
reads, and AMO exclusion also blocks local D reads.

Run from the repository root after `source ./setup.sh`:

```bash
python3 tests/multicore/run.py --private-dcache --private-icache --local-dcache-reads --unit-only --latency 0 3 --work-dir /tmp/wally-l1-unit
python3 tests/multicore/run.py --private-dcache --private-icache --local-dcache-reads --suite atomic --cores 1 2 3 --latency 0 3 --work-dir /tmp/wally-l1-soc
```

The additional capacity cases use the same subsystem top directly; for example:

```bash
verilator --binary --timing --assert -j 2 --top-module msi_tb -GNCORES=3 -GLATENCY=3 -GWORDS=8 -GICACHE_WORDS=2 "-GPRIVATE_ICACHE=1'b1" "-GLOCAL_DCACHE_READS=1'b1" --Mdir /tmp/wally-l1-capacity -Iconfig/shared -Iconfig/rv64gc src/cvw.sv tests/multicore/msi_tb.sv src/ebu/ahbmulticore.sv src/ebu/ahbmsicache.sv
/tmp/wally-l1-capacity/Vmsi_tb
```

The host-local `/tmp/wally-step5/units.py`, `regress.py`, `lint.py` and
`software-checks.py` preserve exact capacity/parameter matrix commands.
The regression runs the same atomic, smoke and UART images with I-only,
D-read-only and both paths, retaining a freshly built blocking baseline.
Cycle counts include startup, synchronization/spinning and interrupt waits;
they are whole-program latency, not a portable IPC measurement.

Initial checks exposed an overly specific old test assumption: an unrelated
valid S line can survive a failed intervention. The ownership assertion now
rejects a new copy of the requested word without rejecting that unrelated
line. This was a test correction, not a changed writeback-error contract.

## Measured two-hart comparison

Same RV64 atomic image, RAM latency 3, 8-word D banks and 64-word I banks
when enabled. Every row passes functionally, including remote code patching
and `fence.i`:

| Configuration | Cycles | External memory transfers | Local replies |
| --- | ---: | ---: | ---: |
| Blocking MSI baseline | 31,788 | 3,024 | 0 |
| Private I only | 13,164 | 806 | 2,374 |
| Local D reads only | 32,768 | 3,168 | 162 |
| Both options | 12,778 | 806 | 2,666 |

The combined case uses 59.8% fewer cycles (2.49x lower elapsed cycle count)
and 73.3% fewer external transfers than the baseline. This workload benefits
primarily from instruction reuse. D-only is 3.1% slower: faster polling
changes interleaving and the amount of work spent spinning. Read-hit
concurrency is not a promise of a speedup for every program. Comparisons do
not establish FPGA clock frequency, area or general Linux speedup.

One full-core build initially raced with a separate derivgen invocation and
could not find config.vh. The missing-include log is preserved as
soc-single-config-race.log; remaining builds were rerun after generation
finished. This was a verification scheduling error, not an RTL mismatch.
