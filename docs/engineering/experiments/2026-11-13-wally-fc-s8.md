# muRISCV-NN fully connected layer with the AI unit (RAW mode)

Status: **simulation (`chipsim-ai`) and Nexys Video (Vivado bitstream of the AI chip with the trace register and RAW) on 2026-11-13**, same results.
Step 3 of [ADR 0024](../decisions/0024-edge-ai-accelerator.md): the library's layer function with the product done by the unit.

## What was built

`asic/librelane/chip/ai/mnn/wally_fc.h` (bare metal, registers at `0x10084000`; the library is used as it is):

- `wally_fc_s8_prepare(folded, w, bias, in, out, input_offset)`: the library adds the input offset to every x, `sum w (x + off) + b = sum w x + (b + off * sum w)`,
  and the unit has no input offset, so the second term is folded into the bias once per layer (TFLite Micro's Prepare step).
- `wally_fc_s8(&ctx, &fc, &quant, &in_d, x, &f_d, w, folded, &o_d, y)`: the arguments of `muriscv_nn_fully_connected_s8` with the folded bias in place of the
  bias and `ctx->buf` a scratch of 4 * output depth bytes. One unit run per batch row in RAW mode, then the library's `muriscv_nn_requantize`, the output offset and the clamp.
  It returns `MURISCV_NN_ARG_ERROR` where the unit cannot take the layer (`wally_fc_s8_unit_ok`: filter offset 0, input depth a multiple of 4 up to 1024, buffers aligned in the RAM outside the trace buffer); the caller then uses the library's function.

`ai/mnn/unit.c` (`make -C asic/librelane/chip/ai/mnn` builds `build/unit.bin`; `chipsim-ai` runs it as `ai_wally_fc`): 60 layers, shapes from 4 x 1 to 1024 x 4,
batches 1 and 2, random input and output offsets, Q31 multipliers (one negative), shifts -16 to +2, clamps, with and without bias, six extreme ones (weights -128, inputs and offsets at the ends of int8); both functions
run on each and every output byte must be equal (the bytes past the outputs are checked too). Then the cycles of the 64 x 64 layer of `mnn/main.c`.

## Results

All 60 layers equal, in simulation and on the board.

| 64 x 64 layer | cycles |
|---|---|
| the library's `muriscv_nn_fully_connected_s8` | 84 393 |
| `wally_fc_s8`: the unit in RAW mode plus software requantization | **10 865** (7.8 times faster) |
| of which the unit's own run | 1 661 |
| the library's requantization of the 64 outputs alone, multiplier and shift at run time | 6 072 (95 per output) |
| `wally_fc_s8_prepare`, once per layer | 68 121 |

About 3 100 cycles are the rest (the loop around the requantization, the clamp, the byte stores, the polling, the register writes); they were not separated.
The requantization is 56 % of the layer or more, the unit's product 15 %: the next step of the ADR (requantizing inside the unit) is where the time is.
The library's 84 393 cycles are 14 more than the 84 379 of the record of 2026-11-12 (another image, the same code; not investigated).

## Not shown

TFLite Micro itself calling it, the Zephyr driver with RAW (`wally_ai_run`), the layers the unit does not take (they fall back to the library), a model of several layers.
