## Observations

- **PASS:** six counter CSR/event unit configurations, RV32/RV64 and
  COUNTERS=3/8/32: fixed events, no double count for returns, invalid retirement,
  zero selectors, inhibition, S/U permissions and rollover/high halves.
- **PASS:** all seven board DTS compile with the generated PMU include; generator
  keeps standard event/counter bounds consistent for reduced counts.
- **PASS:** eight lint configurations, including the dedicated PMU Linux config.
  Host-unsupported `--quiet` is omitted; existing lint exclusions remain.
- **PASS:** full-core hpmcounters coverage, including the two new event sources.
  Standard wsim initially hit the installed development Verilator's missing
  runtime helper VL_SYSTEM_IN(std::string). The final native build supplies
  that host system-call wrapper only inside the generated precompiled header.
  A forced-include attempt was rejected by GCC's PCH rules and was superseded.
  No RTL, test assertions or repository simulator sources are changed by the
  compatibility helper. The host also lacks uv, so bin/elf2hex was invoked
  through Python explicitly. ELF objdump and memfile inputs were generated
  before the passing wsim run. Exact helper/commands/logs are archived.
- **PASS:** actual static RISC-V perf, Linux and OpenSBI images built. Native
  PMU model built from the matching source fingerprint. Checkpoint comparison
  (continuous 100k versus 50k+restore to 100k) is byte-identical.
- **INCOMPLETE/running:** full Linux PMU integration, under its own supervisor.
  No native Linux PMU PASS or FPGA hardware verdict is claimed yet.

The test harness requires a fresh executable/source fingerprint and image
hashes, prevents concurrent work-directory reuse and rejects incompatible
checkpoints. Expected end marker: WALLY_PMU_PASS perf_event_open_and_perf_stat.
No QEMU result is used as proof of Wally's fixed-event semantics. No Sscofpmf,
filtering, overflow sampling, FPGA synthesis or board test is included.
